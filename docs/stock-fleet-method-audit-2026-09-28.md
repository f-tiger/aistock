# 股票产品跨仓方法审计 · 2026-09-28

用户补充：“股票其他几个在 sunwatch，aistock 等仓库”。本轮扩展原任务，不把 agi-site 投资入口上线视为股票产品线完成。

## 三轮 Prompt 修正

1. **范围**：读取真实代码与生产分支，覆盖 SunWatch / Compass / Gushen。区分帮助用户形成可复核投资判断、股票实际回报、站点收费收入三个目标。
2. **对抗方法**：逐项追问“当时是否能知道、能否成交、缺失数据如何处理、比较是否同窗、收益是否扣成本、是否保留失败样本”。代码与独立手算例相互验证，不能仅用旧代码作为正确性标准。没有调用独立多模型评审。
3. **执行与验收**：修复最影响判断可信度的实现缺陷，保留旧记录与方法版本；中英及机器可读输出一致；本地测试、构建、PR CI 和生产验证分别报告，不把任一层通过当成全部完成。

## 发现与修复

### Compass

原生成器采用申报当天收盘价，未核对披露时刻；盘后发布可能引入前视偏差。Put/Call 记录也会按发行人名并入正股，缺价部分按剩余权重归一、缺季度被跳过，全程基准又不一定对应这些保留期。

新版 `13f-next-session-v2` 使用申报日之后的首个完整交易日收盘，排除期权和 PRN，区分 Alphabet 两类股，要求每只股票与 QQQ 在同一执行日有复权价、各期连续；无法完整计算时不生成该经理的成绩。保留 filing `from/to` 供原 Telegram 契约使用，另加 `entryDate/exitDate`、SEC 来源及缺失原因。禁止复权价缺失时静默改用原价。

未重算前，旧 JSON 明确为 `legacy-unverified`，页面及嵌入显示待重算；机器摘要与跟随卡不再推广旧收益。新版仍是**未扣交易成本、税费、滑点的历史模拟**；当前编辑名单存在选择/幸存者偏差，原始 13F-HR 未完整重建修订与保密披露，不能声称已证明可实现超额收益。未成功重算时保留旧文件而不覆盖成空结果。

### SunWatch

旧档案有结果时间早于页面记录日期的描述，不能凭一个日期字段证明全部事前预测。保留全部命中/失误记录，新增发布证据与结果时间字段覆盖，当前完整覆盖为 0；这是未提供完整证明，不等于认定全部判断虚假。二元比率只纳入 hit/miss，pending/partial/未知状态不进入分母。API 区分生成时间与最新记录日期，并明确缺少审计交易和净收益证据。

部署检查改成不触发群发、初始化或行情刷新；现有定时监控不变。既有价格和服务条款没有改动，也没有重新验证旧档案中的所有市场事实。

### Gushen

旧滚动回测把目标权重每天固定，等同于未计成本的隐含日调仓；只在每月 1 日恰好是交易日时调仓，并以首个已变动净值作基数漏计首次成本。新版 `walk-forward-close-v2` 用前一日及更早样本估计，在月内首个可用交易日收盘执行，交易前涨跌归旧仓，间隔持仓自然漂移，成交额成本与首笔费用计入原始本金。

提供同标的池、同窗口、同成本等权基准，以及包含信号数据截止日、成交日、权重、换手、成本的 JSON。目标情景采用历史算术均值与波动作为模型参数，明确固定参数/对数正态假设，不能当作校准后的未来成功率。优化器的历史输出改标为样本内拟合。旧 Python 回测快照保留作历史记录，已知错误不再作为正确性验收；其余 30 个前后端对照/约束验收保留，增加 10 个独立手算/边界测试。

## 为什么这是优先级

“更多推荐股票”与“AI 猜涨跌”不足以形成可信付费价值。更可验证的产品链是：主站建立假设 → FilingLens/Compass 核对披露 → Gushen 检查风险和比较 → SunWatch 跟踪用户已明确订阅的现有事件。当前系统尚未自动贯通为统一研究对象，不能宣称已经一键监控本轮研究表单。

商业验证沿用主站研究报告：先看独立用户是否完成自己的研究、是否复查两次，再验证愿意为持续核验/变更追踪付费。事件次数不是用户数，回测收益不是网站收入。本次未检查新的订单账本、未新增付费证据、未改价格或对外投放。
